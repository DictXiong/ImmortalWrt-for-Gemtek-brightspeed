# umdns 的逻辑网络地址

同一以太网设备可以同时承载 DHCP 管理地址和离线维护地址。umdns 原先枚举设备上的全部 IPv4 地址，发送时由内核选择源地址，可能使用先建立的维护地址。

初始化脚本现在按 `/etc/config/umdns` 中选择的逻辑网络读取 netifd 状态，把管理地址传给 umdns。IPv4 公告、发送来源和单播接收目标使用该地址。没有对应 IPv4 地址时，保留 IPv6 配置并停止该设备的 IPv4 mDNS，不使用其他逻辑接口的地址补位。DHCP 地址变化通过原有接口事件更新。

## 运行时接口

`set_config` 增加可选的 `ipv4_sources` 对象，键为设备名，值为当前已分配的 IPv4 地址。

```json
{
  "interfaces": ["br-lan"],
  "ipv4_sources": {"br-lan": "192.168.1.2"}
}
```

空字符串禁用该设备的 IPv4 mDNS。省略整个对象或某个设备的键时，保留原设备枚举行为。字符串类型、地址格式在更新配置前校验，指定的地址必须实际存在于该设备。单播查询的目标也须属于所选地址集合。共用设备的多个逻辑网络按配置顺序选择第一个有效 IPv4 地址。

另有独立补丁修正 IPv6 hop-limit 的 socket 参数长度，使设置值 255 生效。

## 验证

`scripts/dicttech/tests/umdns/test_config.py` 使用实际 C7 ash、jshn 和模拟 netifd，覆盖首次租约、地址变更、缺少租约、共用设备和多设备，并核对 JSON 命名空间恢复。

实机需核对查询与应答的实际来源、A 记录、排除地址的单播查询，以及缺少地址和租约更新后的行为。接口地址本身、路由和防火墙策略由配置管理。umdns 仅在所配置的逻辑网络上工作，上游网桥仍需允许相应组播转发。
